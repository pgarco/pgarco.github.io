Author

Paulina García-Corral

Why now?

  • First, there has been a shift from methods that involve the manual engineering of text into numerical representations.

  • Second, large pre-trained models have led to greater accuracy while reducing data requirements.

  • Third, and more recently, there has been a shift from programming to an interface that uses natural language inputs and outputs.

    (Than et al. 2025)

Why us?

Before GenAI researchers that were using computational tools for their work had to have some understanding of what they were using because the entry barrier has hefty:

  • Scrape the data

  • Annotate the data

  • Write the code

  • Deal with the computational equipment

The line between using AI as a tool, and studying the tool was a bit more blurry. Three years ago, we became the LLM “experts” because we could code a Python loop that called an API 😂

With the current advances of GenAI, it’s really not the same to use AI as a tool in research and researchers who study AI.

Is this computational social science?

Lowering the technical barrier to use GenAI can mean different things to different people, but when non-computational researchers use GenAI tools, what are the doing methodologicaly?

a. Come up with new research ideas? (research design)

b. Pass on their research work to an agent (speed up or automate)

c. Integrate new methods into their research (mix methods)

d. Evaluate their analysis (data saturation checks, triangulation)

e. Prepare and revise manuscripts (write up and edition work)

When we teach AI to or review AI use of non-experts

We need to restructure the use and engagement of GenAI, and move away from using AI passively to get to a place where we convince non-computational researchers that they can and should be interrogating it systematically.

This implies

  1. Intuition
    Understand what LLMs do and why they behave as they do

  2. Interaction
    Learn how to work with LLMs beyond chat and copy-paste

  3. Evaluation
    Critically assess outputs (bias, limitations, variation)

  4. Documentation
    Make the process transparent and reproducible*

Modes of Combining Computation and Qualitative Analysis

A key consideration is how—or whether—to integrate computational tools into the analytical workflow. Researchers adopt different modes based on project needs, data sensitivity, and analytical goals.(Abramson et al. 2025)

  1. Streamline (Organizational):
  • Using computational tools to manage the logistics of research—organizing manifests, facilitating de-identification, managing quotes, and tracking team progress—even if the core coding and analysis remain entirely manual.
  1. Scale-up (Efficiency/Scope):
  • When the corpus is large, longitudinal, or multi-site, machine learning (e.g., supervised classification) is used to assist human coding. This requires high-quality human-labeled training data and rigorous human checks and validation (e.g., hybrid approaches).
  1. Hybrid (Iterative Refinement and Mixed Methods):
  • Interleaving human analysis with computational methods to answer different types of questions or refine understanding. This can involve iterative coding refinement, or using computational patterns (e.g., visualization, network analysis) to identify typologies or variations that guide subsequent in-depth reading and comparison
  1. Discovery (Pattern Finding):
  • Utilizing unsupervised methods (e.g., topic modeling, clustering, visualization) to identify latent patterns, themes, or typologies that guide subsequent deep reading and theory development
  1. Minimal/No Computation (The “Sociology of Computation”):
  • Deliberately choosing not to automate analysis when ethical considerations, highly specific contexts, small scale, or the nature of the inquiry make automation counterproductive or risky. Documenting the rationale for this choice is practical, given review– explaining reflexivity and decisions has long been central to qualitative inquiry

Goal 3: Evaluating Outputs

Develop critical AI literacy, such that scholars are aware of why, what and how there come up:

  • Hallucination

  • Bias

  • Loss of nuance

  • Overgeneralization

Teaching strategy

Contrast-based learning

Activity

Human vs AI comparison

  1. Learners analyze a text manually

  2. AI analyzes the same text

  3. Compare:

    • What did AI miss?

    • What did it oversimplify?

Goal 4: From Ad Hoc Use to Workflow Thinking

Introduce structure and repeatability (here we enter interesting epistemic territory)

  • Iterative refinement

  • Batch thinking (even without code)

Replace copy-paste prompting with structured processes.

Activity

  • Test it across multiple inputs

Pedagogical Principles

  1. Teach through interaction, not explanation
  2. Use progressive disclosure
  3. Design for productive failure
  4. Anchor everything in real tasks
  5. Reduce intimidation, enable exploration
  6. Emphasize learner expertise

Teach through interaction, not explanation

  • Minimize lecturing
  • Maximize hands-on experimentation

Use progressive disclosure

Teach in layers:

  1. What it does

  2. When to use it

  3. How it works

Design for productive failure

  • Include exercises where AI fails
  • Let learners discover limitations

Anchor everything in real tasks

Never introduce a tool without a use case:

  • coding interviews

  • summarizing texts

  • generating themes

Reduce intimidation, enable exploration

  • Normalize confusion
  • Encourage experimentation
  • Avoid perfectionism
  • Use metaphors

Emphasize learner expertise

The model generates outputs but the human interprets them.

Evaluate the whole process, not just the output

Good assessment includes:

  • Prompt design quality

  • Ability to critique outputs

  • Documentation completeness

  • Reflection on limitations

Final guiding statement

The goal is not to make researchers proficient in AI, but to make them thoughtful, critical, and systematic users of it.
