Coding text

Traditional quantitative approaches

Coding is sorting text into categories. To categorize text quantitatively we usually use content analysis + some statistics

  • Top frequency

  • Keyword search

  • Dictionary approaches

Quantitative coding makes a leap between the presence of certain words and the meaning of a document.

Qualitative coding

Qualitative coding relies on human expertise to interpret meaning, which is nuanced and contextual.

How do we capture meaning and its complexity into discrete categories?

Qualitative code building

When we code text we are building the categories. It’s an iterative, reflexive process, based on reading the passages and connecting theory, documents, and passages between them.

Thematic patterns depend on situational framing and they emerge relationally.

Context is hard

Context is what tells us what the text means. Context is what brings about meaning. Text interpretation depends on who is speaking, to whom, where and when.

This extends further, for example sarcasm, innuendo, regional interpretations…

Traditional quantitative text analysis methods struggled with this.

# Normalize text: lowercase, remove symbols/punctuation
normalize_text <- function(text) {
  text <- tolower(text)
  text <- gsub("[^a-z0-9 ]", " ", text)  # remove punctuation
  text <- gsub("\\s+", " ", text)        # collapse whitespace
  trimws(text)
}

# Apply normalization to lyric column
df$clean_lyric <- sapply(df$lyric, normalize_text)

# Define normalized keyword list
keywords <- c("u s a", "america", "united states")

# Keyword counting function
count_keywords <- function(text, keywords) {
  sapply(keywords, function(k) {
    pattern <- paste0("\\b", k, "\\b")
    matches <- gregexpr(pattern, text)[[1]]
    sum(matches > 0)
  })
}

# Create keyword count table
keyword_counts <- t(sapply(df$clean_lyric, function(song) count_keywords(song, keywords)))
# Add row names from song column
rownames(keyword_counts) <- df$song
colnames(keyword_counts) <- keywords

# Output the final table
keyword_counts

Bigger scale, bigger stakes

With the advent of LLMs, one big change in the NLP ecosystem has been the availability of the models.

As models increase their capabilities, their training is much more expensive, the risks are considerable, and companies start competing.

The NLP ecosystem has moved from pure research incentives, to financial and commercial, creating with it a bimodal ecosystem: with closed-source frontier models on the one side and open-source models on the other.

Open-source vs. closed-source LLMs

Open source, publicly available, published, open for studies:

  • Meta’s LLama, Google’s Gemma, Alpaca, some versions of Mixtral, etc.

Close source, proprietary, black-boxes:

  • all OpenAI from GPT3s on, Google’s Gemini, Claude, etc.

(“Open source” is a bit misleading)

Open vs. Closed re context

During pretraining, models learn language patterns from data, and build deep contextual knowledge from that data following certain architectural (or model design) choices.

Why LLMs for coding texts from a qualitative perspective?

LLMs have opened new avenues for text analysis:

  1. The size and context seem to increase interpretative and analytical capabilities.

  2. Models don’t need to be fine-tuned for each corpus.

  3. Lower the entry barrier (no coding needed, just prompt).

What is a prompt?

Google AI: “A prompt is a natural language request submitted to a language model to receive a response back. Prompts can contain questions, instructions, contextual information, few-shot examples, and partial input for the model to complete or continue.”

Prompt Engineering for coding tasks

How can we use LLMs to translate quantitative approaches while adding qualitative nuance?

Through the prompt we can guide and set the “tone” for the model to add context and intention for our coding needs.

Parts of a prompt

System + User + Repose

“You are a helpful assistant that can write history essays for 9th grade global history. Please complete an essay answering the following question: Compare and contrast World War I and World War II. Write like a 16 year of high school boy”

Sure, here is an essay that compares and…

Parts of a prompt

System: instructions that get passed to the model before any user input. They are used to dictate the style and tone of the model, add constraints, set expectations of what the system is supposed to do.

You are a text classification model specialized in gender studies and qualitative text analysis. You need to label text as misogynistic or not.

User: specific questions that you want answered within the context of the system.

Classify the next tweet: Woman should stay home and clean the house. They have no business being in serious places like banks and government.

Response: the model output or prediction.

Sure. I would label the tweet as misogynistic as it considers that women should not participate as equals in public life. Is there any other text I should label for you?

How to build a good prompt

  1. Be as specific as possible about task (Your task is to classify EU policy reports)
  2. Delimit a role (You are a… )
  3. Explain output expectations (Answer should be limited to yes or no)
  4. Provide tone and audience cues (This is intended as research on feminist views on…)
  5. Add examples
  6. Give feedback to refine

Steps

  1. Define task
  2. Write prompt
  3. Test prompt
  4. Evaluate results
  5. Refine prompt
  6. Deploy

Components to consider

Let’s talk about…

  • Models! Understanding what types of models exist and what they’re good at is essential when deciding how to use LLMs effectively.

  • Memory! It determines what the model can keep track of, both inside its context window and in the hardware that runs it.

  • Computation! Efficient computation ensures the model responds quickly and at reasonable cost, depending on the hardware and workload.

Models

Different architectures influence reasoning ability, hallucination rates, domain expertise, and performance. Selecting and tuning an appropriate model ensures the system meets the task’s complexity and quality requirements.

  • Size: number of parameters, quantization levels, and how they affect accuracy vs. speed

  • Type: text-only, visual, multimodal, or specialized reasoning models

  • Performance: throughput, latency, quality of outputs, and robustness across tasks

Memory

  • Internal to the model — context length, token limits, embeddings, and use of vector databases for retrieval

  • External to the model — the physical memory requirements (e.g., how many GB of RAM or VRAM are needed to load and run the model)

Computation

Computation covers the hardware and processing needed to run LLMs efficiently. It shapes inference speed, scalability, and cost.

  • Hardware choices (GPU vs. CPU, etc)

  • Throughput and latency (how fast a model can generate results)

  • Scalability (batching, distributed inference, and overall resource utilization)

What is Retrieval-Augmented Generation (RAG)

A method that enhances LLMs by combining them with external knowledge sources.

  • Combines a language model with a retrieval system

  • Pulls relevant information from databases or documents

How RAG Works

Two-step process: Retrieve + Generate

  • Retrieve: Search a document store or database using embeddings

  • Select: Identify the most relevant passages or chunks

  • Augment: Feed these retrieved texts into the model’s context

  • Generate: Model produces answers grounded in the retrieved evidence

Why RAG?

Better accuracy, reliability, and domain alignment

  • Accuracy: Reduces hallucinations

  • Flexibility: Uses your domain-specific datasets

  • Traceability: Supports citations & verifiable claims

  • Efficiency: No need for costly model training

  • Up-to-date: Injects current or changing information

Few-shot learning

Teaching the model through examples: you guide an LLM by giving it a handful of examples directly in the prompt.

  • Provide a small number of examples in the prompt

  • Model uses these examples to understand the task

  • No fine-tuning needed

How Few-Shot Learning Works

Examples → Pattern recognition → Output

  • You insert 2–10 examples of the task into the prompt

  • Model identifies the structure or pattern of the examples

  • New query is appended at the end, and the model continues the pattern to produce the answer

Few-Shot

Few-shot learning is powerful because you can instantly adapt a model to your domain or style without any technical overhead. For social science, it’s especially useful for coding qualitative data, standardizing text, or guiding complex reasoning.
